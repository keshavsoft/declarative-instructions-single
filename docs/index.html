The table story

Each instruction fills one part.

The sample starts from spec.tableWithFooter, an empty table AST with marked colgroup, header, body, and footer targets.

01 / CLONE THE SHELL

Keep the spec reusable

The sample clones the base table before changes are made. The cloned object becomes the canvas passed to the runner.

02 / SUPPLY TABLE DATA

Columns define the shape

Three column definitions describe Item Name, Category, and Base Unit. Three records provide the values for the body rows.

03 / RUN SINGLE KEYS

Fill each table region

Separate keys build widths, header, body, footer, and the search controls. A later single key adds serial values to body rows.

One table instruction

Rows meet columns at the body.

`buildBody` is the table’s two-dimensional step. It takes the records and column metadata, then places generated rows under the spec’s `table-body` role.

src/v3/instructions.jsonbuildBody
{
  "buildBody": {
    "type": "rowOnColumn",
    "narration": "Build table body",
    "sourcePath": {
      "rows": "$.data.data",
      "columns": "$.data.columns"
    },
    "destinationPath": {
      "jsonPath": "$..*[?@.attributes['data-role'] == 'table-body'].children"
    },
    "templateKey": {
      "rowKey": "buildBodyTr",
      "columnKey": "buildBodyCell"
    },
    "func": "rowOnColumn"
  }
}
The other single steps

buildColgroup, buildHeader, and buildFooter each map the column definitions into their matching table destination. Search is added as a toolbar plus label, helper, and input slot instructions.
