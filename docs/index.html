The catalog story

Each key describes one atomic operation.

The V5 catalog gives a runner the source path, transformation, template, and destination it needs for one step.

01 / LOCATE INPUT

Read the needed values

sourcePath identifies data such as columns and records. Static template insertions can omit a source.

02 / SHAPE OUTPUT

Choose a function and template

func selects how values are mapped; templateKey selects the reusable spec shape.

03 / PLACE RESULT

Write to one destination

destinationPath identifies the target in the existing JSON tree for this operation.

One instruction

Rows meet columns at the body.

buildBody reads records and column metadata, combines row and cell templates, then targets the table body.

src/v5/instructions.jsonbuildBody
{
  "buildBody": {
    "type": "rowOnColumn",
    "narration": "Build table body",
    "sourcePath": {
      "rows": "$.data.data",
      "columns": "$.data.columns"
    },
    "destinationPath": {
      "jsonPath": "$..*[?@.attributes['data-role'] == 'table-body'].children"
    },
    "templateKey": {
      "rowKey": "buildBodyTr",
      "columnKey": "buildBodyCell"
    },
    "func": "rowOnColumn"
  }
}
The package covers more than tables

The catalog also describes forms, selects, datalists, accordions, cards, lists, list groups, menus, and menu cards. Search controls are separate named steps.
Reference a key

Let the runner perform the operation.

The catalog exports definitions. A step descriptor tells a compatible executor which one to retrieve.

Instruction referencesingle step
import singleInstructions from "declarative-instructions-single";

const body = singleInstructions.buildBody;

const descriptor = {
  type: "single",
  key: "buildBody"
};

The runner provides the current state, applies the definition, and mutates the target JSON tree. This package only supplies the named operation.
