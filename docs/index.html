The story

Keep the assembly readable.

The original report grew into two complementary patterns. This one favors small, named operations that can be inspected and composed individually.

01 / LOCATE

Choose the destination

A JSONPath points to a table row, form body, card slot, or another mount point in the base tree.

02 / MAP

Describe the source

A value or collection is read from the input. A standard function maps it when the transformation needs one.

03 / ASSEMBLE

Name the blueprint

A template key connects the instruction to a reusable node definition supplied by the spec package.

INPUTcolumns, rows, items
SOURCE PATHselect the data
FUNCTIONmap or apply
TEMPLATE KEYshape each node
DESTINATIONmount into the tree
A real contract

Table headers, without a hidden loop.

The instruction connects input columns to a named header template and places the result in the header row.

src/v3/instructions.jsonbuildHeader
{
  "buildHeader": {
    "type": "single",
    "narration": "Build table header",
    "destinationPath": {
      "jsonPath": "$..*[?@.attributes['data-role'] == 'table-header-row'].children"
    },
    "sourcePath": "$.data.columns",
    "templateKey": "buildHeader",
    "func": "fromCollection"
  }
}
Why this pattern?

Each key stays small enough to understand by itself. The catalog ranges from table assembly to form fields, select options, cards, accordions, lists, and menu items. The compiler interprets the contract; this package does not ship a renderer or the templates themselves.
